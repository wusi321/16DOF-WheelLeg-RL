# 总场地（14m × 6m 完整赛场）

把之前分别做的 8 个障碍，拼成一块 14000mm × 6000mm 的完整赛场，用于整体预览和后续联调。

**不是训练地形**——训练还是用各个场地文件夹里那套独立的 patch（每个障碍单独练效率更高）。
这里的作用是：一眼看到 8 个障碍按官方布局摆在一起是什么样，以及验证它们能不能同时放进场地。

---

## 1. 怎么用

### 看场地
双击 **`查看总场地.bat`**，会打开 MuJoCo 预览窗口（俯视整个 14×6m 场地）。

命令行参数：

```bat
查看总场地.bat                  :: 打开窗口
查看总场地.bat --no-window      :: 只加载并打印统计，不开窗口
查看总场地.bat --rebuild        :: 先重新生成 XML 再预览
```

### 重新生成

```powershell

& "D:\Project\wheelleg-rl\.venv\Scripts\python.exe" `
```

**排布严格按官方图 1-2 的相对位置**：


脚本每次运行都会自检，当前结果：

```
硬约束（不重叠 + 距边界 >= 0.60m）：
```

对应规则 3.1 的三条要求：

| 规则要求 | 实际 | 状态 |
|---|---|---|

| 障碍之间距离 >= 800 mm | 最小 **0.80 m** | ✓ |

## 5. 三个关键设计决定

### 5.1 每个障碍只放 1 个实例

训练用的课程地形里有重复实例——比如**高墙训练时一个 patch 里放 5 面**（为了让机器人连续翻 5 次，训练信号更密集）。
但**比赛现场每个障碍只有一个**，所以总场地里高墙只生成 1 面：

```python
kwargs=dict(size=(2.0, 1.2), wall_centers_x=(1.0,))
```

### 5.2 地面只铺一块

每个 terrain 类的 `function()` 都会先用 `make_plane()` 铺一块自己的地面（`geometries[0]`）。
8 个拼在一起就是 8 块地面重叠。

所以脚本对每个障碍**把 `geometries[0]` 删掉**，最后统一铺一块 14×6m 的黄色场地地面。

### 5.3 直接复用已验证的地形代码

每个障碍都是调用 `src/robot/terrains/` 里对应的 `SubTerrainCfg.function(1.0, spec, rng)`，
难度固定 **1.0 = 官方表 1 规格**。

好处：总场地里的每个障碍，跟单独训练时跑的是**同一份代码、同一套参数**，不会出现"训练场和演示场不一致"。

## 6. 和参考仓库的关系

布局基准取自 `uwvwko-zzz/27rc-dog-race` 的 14×6m 排布（源码在 `../参考-官方赛场/`），
但**几何全部用我们自己的实现**，并按我们的实际包围盒重新避让过。

参考仓库是第三方训练解释，它自己在 XML 注释里就写了：

> *Layout is a training interpretation of Fig. 1-2, not the unpublished competition layout.*

也就是说**官方并没有公布固定布局**（规则原文：「其具体排列顺序与安装位置在赛前公布」）。
所以这里的布局只是一种合理的排法，不是"官方标准答案"。

两种实现的差异对比见 `../参考-官方赛场/README.md`。

## 7. 已知限制

| 项 | 说明 |
|---|---|
| 没有机器人 | XML 里只有场地，没挂机器人模型。要看机器人跑，得用训练环境 |
| 没有判分逻辑 | 这只是几何模型，越障成功/失败判据在 mdp 层，不在这里 |
| 间距按**包围盒**算 | 规则里的"障碍间距"通常指主体结构之间，不含必达区/虚线这类标记物。我们的包围盒含标记物，所以算出来偏保守 |
| 障碍朝向未严格复刻参考仓库 | 例如沟壑组合，参考仓库是台阶朝 +x 上坡，我们的是台阶朝 -x。规则不规定朝向，L 形结构本身是对的 |
