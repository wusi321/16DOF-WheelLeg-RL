## 一、为什么要做这个

官方比赛时，8 个障碍是**挨着摆在一个 14m × 6m 的场地上**的，机器人要连续通过。
单独练一个障碍容易练出"只会在干净场地上做那一个动作"的策略。

组合场地把两个障碍**并排**放在一个 patch 里，逼它面对"刚跨完沟、马上就要绕桩"的切换。

**当前组合**：

| 列 | 障碍 | 官方规格 |
|---|---|---|
| 列 1 | **沟壑组合** | L 形；平台 360mm 高 / 800×800；沟宽 360mm；台阶 320×120；斜坡 20° |
| 列 2 | **绕桩** | L 形 6 桩，⌀100mm × 高 100mm，中心距 900mm，3 个必达区 ⌀300mm |

两个障碍的单独说明见：
- `沟壑组合/场地/README.md`
- `绕桩/场地/README.md`

## 二、地形尺寸

| 项目 | 值 | 说明 |
|---|---|---|
| patch 尺寸 | **6.0 × 3.2 m** | 两列各占 6.0m 长；3.2m 宽是为了装下两个 L 形 |
| 列数 | 2 | 沟壑组合 + 绕桩 |
| 难度关卡 | 10 档 | 0~9 |
| 回合 | 28 秒 | |

**为什么宽到 3.2m**：绕桩在官方规则里是 L 形（水平臂 2.7m + 竖直臂 1.8m），
沟壑组合也是 L 形（斜坡要往 +y 拐出去约 1m），1.6m 的宽度都装不下。
这是 2026-11-28 改的——之前用 1.6m，两个 L 形都被裁掉了。

## 三、终点距离（这里之前有个 bug，已修）

终点判定 `reached_goal(distance=...)` 比的是**机身沿 +x 相对起点走过的距离**。

旧值 `COMBO_GOAL_DISTANCE = 4.8`（= 6.0 − 0.8 − 0.4，从"一字排开的跨沟"算出来的）。
换成 L 形之后，两列实际能走的距离是：

| 列 | 起点 x | 最远可到 x | 可推进 |
|---|---|---|---|
| 沟壑组合 | ≈5.75 | 平台 B 左边界 ≈2.85 | **2.90 m** |
| 绕桩 | ≈0.35 | 末端桩 ≈4.05 | **3.70 m** |

**4.8m 两列都走不到 → 终点奖励恒为 0，等于白设。**

现在改成 **2.8 m**：沟壑列刚好跨过沟、走完平台 B；绕桩列走过大半排桩。

## 四、训练命令

任务名：**`Robot-16DOF-Combo-v0`**

```powershell
$root="D:\Project\nano\16dof-rl"; $py="D:\Project\wheelleg-rl\.venv\Scripts\python.exe"
$env:PYTHONPATH="$root\src;$root\mjlab\src"; $env:PYTHONIOENCODING="utf-8"
$env:WARP_CACHE_PATH="$root\.cache\warp"; $env:TMP="D:\Project\nano\.tmp"; $env:TEMP=$env:TMP
Set-Location $root

& $py -u train_16dof.py Robot-16DOF-Combo-v0 --agent.max-iterations 1500 --agent.run-name "combo_第一轮"
```

**建议**：先在两个障碍上分别练到能过，再用组合练"切换"。
一上来就组合练，两个都过不了，梯度信号会乱。

## 五、奖励构成（和单场地不同的地方）

组合场地同时跑了两套判据：

| 奖励项 | 权重 | 属于 |
|---|---|---|
| `forward_progress` | 2.0 | 通用 |
| `goal_reached` | 60.0 | 通用（距离 2.8m） |
| `waypoint` | 5.0 | **绕桩专属** |
| `all_waypoints` | 30.0 | **绕桩专属** |
| `skip` | −30.0 | **绕桩专属**（漏必达区） |
| `pillar_hit` | −5.0 | **绕桩专属**（撞桩） |
| `leap`（`leap_bonus`） | +5 | **沟壑专属**（离地后落地） |

判据函数是"只在对应列生效"的（`*_on_slalom` 后缀那些会检查自己是不是踩在绕桩列上）。
