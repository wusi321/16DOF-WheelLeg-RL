## 一、这是什么

一份**完整的 14m×6m 障碍赛场地**，8 个障碍按图 1-2 的位置一次性摆好，可以直接用 MuJoCo 打开看整体布局。

我们自己的 8 个场地是**独立训练 patch**（每个障碍一块地，方便课程学习），没有拼成完整赛场。这份参考补的正是"整场长什么样"。

```
maps/obstacle_course_2027.xml   ← 完整赛场（984 个 geom，可直接加载）
maps/task_course_2027.xml       ← 任务赛场地（6×4m，另一赛项）
原始脚本/generate_course.py     ← 生成上述 XML 的脚本（144 行，参数都在里面）
原始脚本/modeling-原文.md        ← 作者的建模说明（尺寸表 + 近似假设）
```

**看一个场地长什么样：**

```powershell
$py="D:\Project\wheelleg-rl\.venv\Scripts\python.exe"
& $py -c "import mujoco, mujoco.viewer; m=mujoco.MjModel.from_xml_path(r'C:\Users\gqj28\Desktop\16DOF-WheelLeg-RL\参考-官方赛场\maps\obstacle_course_2027.xml'); d=mujoco.MjData(m); mujoco.viewer.launch(m, d)"
```

## 三、⚠️ 最关键的一件事：规则有 V2.0

参考仓库 README 明确写：

> 障碍赛已按 **V2.0（2026-10-29）** 更新：**梅花桩及两端平台高度为 100mm**，轮胎为黑色。
>
> 更新日志：按比赛规则 V2.0 更新障碍赛地图：梅花桩方块由 200×200×200mm 改为 **200×200×100mm**，两端平台由 800×800×200mm 改为 **800×800×100mm**，底面保持贴地。

而我们手上核对的是 **V1.0** PDF（梅花桩 200mm）。两者的差别就在这里：

| | V1.0 | V2.0（参考仓库） |
|---|---|---|
| 梅花桩方块 | 200×200×**200** | 200×200×**100** |
| 两端平台 | 800×800×**200** | 800×800×**100** |

**这个差别很要命**：我们机器人轮子直径 168mm。
- 桩高 **200mm > 轮径** → 轮子完全顶在竖直面上，一点推力都用不上，必须纯靠腿把 25kg 机身举上去
- 桩高 **100mm < 轮径** → 轮子能"骑"上去，腿只需辅助

所以：**如果 V2.0 是现行规则，梅花桩就不再是"过不去"的障碍，而是常规可过障碍。** 这也解释了为什么之前训练一直卡在 ~155mm —— 那正好是接近轮径的位置。

仓库的 `docs/reference/` 目录本该放 V1.0 和 V2.0 两份 PDF，但被 `.gitignore` 排除了，所以拉不到 V2.0 原文。

**在拿到 V2.0 原文确认之前，不要按 100mm 去改训练地形。**

## 四、可以借用的东西

1. **完整赛场布局**（哪个障碍摆在哪、间距多少）—— 直接看 XML，或跑上面的预览命令。
2. **梅花桩的正确排布**（6 个、3.5m、首块净距 100/400、末块 400/100、中心对称）—— 这一条 V1.0 和 V2.0 是一样的，和高度无关，可以直接用到我们的地形里。
3. **虚线的画法** —— 它用 capsule `fromto` 画短线段（`square()` / `line()` 函数），比我们堆小方块更省 geom。

## 五、不要照抄的地方

- **它的台阶高度不是 120mm**：脚本里台阶顶面是 0.12 / 0.06，高差 0.24 / 0.06，和规则"台阶高度 120mm"对不上（它的 `modeling.md` 自己也写"高差 0.12"，和脚本对不上）。我们的 0.12 / 0.24 / 0.36 才是每级 120mm。
- **它没有判据**：README 最后一句写明"目前未实现判分"，绕桩路线、台阶接触次数、场外足端比例都没做。我们的 `mdp/` 有这一层。
- **摩擦参数是它自己的训练值**（默认 0.9、轮胎 1.1），不是规则值。
- **轮胎用 48 个环形扇区拼的**，一个轮胎 48 geom，8 个轮胎 384 geom —— 我们用一个圆环就够，没必要跟。
