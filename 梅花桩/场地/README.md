## 1. 这是什么场地

按《2027 年足式机器人挑战赛 **V2.0**（2026-10-29 修订）》障碍赛「梅花桩」条目复现：

| 项目 | 规格 | 说明 |
|---|---|---|
| 桩尺寸 | 200 × 200 × **100** mm | 顶面高 **0.10 m**（V1.0 是 200mm，V2.0 减半） |
| 桩数量 | **6 个**（两排各 3 个） | 规则里就是 6 个方块，不随赛道长度变 |
| 同排桩距 | 0.60 m（中心距） | 净距 0.40 m；> 轴距 0.387 m，**必须抬腿跨，不能纯滚过去** |
| 两排间距 | 0.40 m（中心距） | 净距 0.20 m；≈ 轮距 0.385 m，左右轮各踩一条桩列 |
| 两排错位 | 0.30 m | 梅花形交错 |
| 首块距平台 | 100 mm / 400 mm | 两排分别，规则明文 |
| 末块距平台 | 400 mm / 100 mm | 与首块对称，整体中心对称 |
| 起终点平台 | 800 × 800 × **100** mm | 与桩顶齐平（V1.0 平台是 200mm 高） |
| **赛道总长** | **3.5 m** | 平台 0.8 + 桩区 1.9 + 平台 0.8（2026-11-28 从 8.0 m 改回官方尺寸） |

> **长赛道选项**：以前的 8.0×1.6 m 加长版还留着，设环境变量
> `STEPSTONE_LONG_TRACK=1` 就切回去（终点 6.8 m、回合 30 s）。那是训练手段，不是官方尺寸。

> ✅ **V2.0 已核对（2026-10-29 修订）**：拿到官方 V2.0 原文后确认，梅花桩
> 方块从 200×200×200 改为 **200×200×100**，两侧平台从 800×800×200 改为
> **800×800×100**。本场地已按 100mm 生成。
>
> 这个改动在物理上是质变，不是量变：轮径 **167.8mm**，V1.0 的 200mm 桩比轮子
> 还高 32mm，轮子顶在竖直棱面上推力为零，必须纯靠腿举 25.1kg 机身；V2.0 的
> 100mm 桩比轮子矮 68mm，轮子能直接"骑"上棱边，腿只需辅助。

训练用地形是**代码程序化生成**的（不是 3D 建模）：方块的位置、尺寸全写在
`stepping_stones.py` 的参数表里，难度 0→1 之间自动插值出 10 个等级——
第 1 级桩高只有 2~3 cm（几乎平地），第 10 级才到实场的 **10 cm**。

## 2. 怎么训练

```powershell
$root="D:\Project\nano\16dof-rl"; $py="D:\Project\wheelleg-rl\.venv\Scripts\python.exe"
$env:PYTHONPATH="$root\src;$root\mjlab\src"; $env:PYTHONIOENCODING="utf-8"
$env:WARP_CACHE_PATH="$root\.cache\warp"; $env:TMP="D:\Project\nano\.tmp"; $env:TEMP=$env:TMP
Set-Location $root

# 从头训
& $py -u train_16dof.py Robot-16DOF-StepStone-v0 --agent.max-iterations 1200 --agent.run-name "自定义名字"

# 接着某个模型往下训（把 XXXX 换成日志目录名，YYYYY 换成模型文件名）
& $py -u train_16dof.py Robot-16DOF-StepStone-v0 --agent.resume True `
    --agent.load-run "2026-11-28_11-43-52_round9fix_p8_frontcenter" `
    --agent.load-checkpoint "model_28681.pt" `
    --agent.max-iterations 1200 --agent.run-name "下一轮名字"
```

> **坑**：`--agent.resume` 必须显式写 `True`，只写 `--agent.resume` 会报
> `invalid choice '--agent.load-run'`。

**训练完怎么量成绩**（两个脚本配合）：

```powershell
# ① 综合体检：站姿、半跪、腿穿模、后轮踩空、支撑轮数、覆盖率、前进距离
& $py eval_stepstone_16dof.py --checkpoint "<模型路径>.pt" --out "$root\eval.json"

# ② 落点测量：前轮/后轮各自离桩心多远、多少比例落在 ±3cm 内
& $py measure_landing_16dof.py --checkpoint "<模型路径>.pt" --out "$root\landing.json"
```

两个脚本都固定 `seed=42`、10 个并行环境、30 秒（1500 步），所以**不同模型面对的
地形完全一致，可以直接对比**。

## 3. 关键参数在哪、怎么改

**这是本场地最容易踩的坑**：参数分两个地方，而且 `task_16dof.py` 里的常量会
**覆盖** `env_cfgs.py` 里的权重——只改 env_cfg 是不生效的。

| 参数 | 位置 | 当前值 | 作用 |
|---|---|---|---|
| `LANDING_EDGE_WEIGHT` | `task_16dof.py` | **−1.2** | 轮子偏离桩心的惩罚权重 |
| `BODY_HEIGHT_WEIGHT` | `task_16dof.py` | **−8.0** | 机身趴低惩罚（−8 比 −5.5 更趴） |
| `REAR_GAP_WEIGHT` | `task_16dof.py` | **−65.0** | 后轮踩空惩罚 |
| `WHEEL_SUPPORT_WEIGHT` | `task_16dof.py` | **0.4** | 支撑轮数奖励 |
| `BODY_HEIGHT_MIN` | `task_16dof.py` | 0.30 m | 低于此高度开始罚 |
| `wheel_airtime.min_support` | `env_cfgs.py` | **2** | 至少几轮着地（3 改 2 是最大突破） |
| `landing_precision` | `env_cfgs.py` | 权重 2.2 | 落点精度给分 |
| `precision_window` | `env_cfgs.py` | **0.6** | 前轮给分窗口（归一化，0.6 = 6 cm） |
| `rear_window` | `env_cfgs.py` | **0.45** | 后轮给分窗口（4.5 cm） |

## 4. 踩过的坑（**接手前必读**）

### 4.1 惩罚给重了，它会"学会摔死逃避"

把落点惩罚从 −0.8 加到 −3.0，训练 100 轮内策略直接崩：覆盖率 0.25→0.015、
摔倒率 0.85→21、地形等级 3.47→0.86。

原因：−3.0 的权重下每回合罚 −3.6，而所有正向奖励加起来才约 2.0。
**惩罚超过总收益，最优策略就是让回合早点结束。**

**规律：惩罚的绝对值不要超过正向奖励的总和。**

### 4.2 惩罚没有"接触门控"，会罚到正常跨缝动作

第二版把权重放到 −0.8 仍然崩，而且崩在"地形等级刚好练到 5.9"的时候。
原因：轮子在桩**外面**也算偏离，于是正常跨缝被当成犯错。

修法：加"轮子真的接触到桩顶"的门控（`contact` + `max_norm=1.5`），
让判据只在"踩上去了但没踩准"时生效。修完立刻突破 5.9 的天花板，到 6.25。

### 4.3 给分窗口太窄 = 没有梯度，等于白给

`landing_precision` 原本只在轮心离桩心 **5 cm 内**给分。而前轮实际落在
5~7 cm，**窗口外梯度恒为 0**——所以权重从 1.6 加到 2.2 毫无变化。

修法：窗口放宽到 7.5 cm（p8）。结果后轮从 4.44 → 3.93 cm，但**前轮没动**
（4.68 → 4.62）——因为它停在 4.7 cm 也有分拿，等于给了它一个"及格点"。

### 4.4 窗口收到 3 cm + 重罚（−2.0）= 全面倒退

p9 实测：前轮 4.56、后轮 4.47（比 p8 的 3.93 更差）、±3cm 内只有 33.9%，
**两轮的"上桩率"各掉 7~8 个百分点**。

原因还是 4.1 的回避行为：罚重了它干脆**少踩桩**。

### 4.5 `min_support` 从 3 改 2 —— 最便宜的一次大突破

"至少 3 个轮子着地"这个约束太死，机器人为了凑数会做出怪动作。
改成 2 之后**同时改善了四项指标**：踩空率、支撑轮数、腿穿模、机身高度。
前 3 轮死磕落点惩罚都没能超过的 2.60% 踩空率，一次就过了。

**教训：约束类的参数比奖励权重更有效。**

## 6. 还没解决的

1. **前轮落点拉不进中心**。后轮已经能到 3.93 cm，前轮一直在 4.5~4.7 cm 不动。
   可能是物理限制：前腿是探路腿，必须先伸出去找桩面才能承重。
   下一步试的方向是**前后轮分开设标准**（给分窗口前 0.6 / 后 0.45）。
2. **速度和姿态互相拉扯**。机身趴得越低（半跪 0.136）走得越慢（3.92 m）；
   站得高（半跪 0.20）能到 4.74 m。这是物理上的取舍，不是调参能绕过的。
3. **`eval_stepstone_16dof.py` 没有摔倒率指标**，需要看摔倒得靠训练日志。

## 7. 文件清单

```
梅花桩/场地/
├── README.md                        ← 本文档
├── src/robot/terrains/
│   └── stepping_stones.py           ← 地形定义（放回 src/robot/terrains/）
├── src/robot/mdp/
│   └── stone_coverage.py            ← 落点/踩空/覆盖率 判据（放回 src/robot/mdp/）
└── config/
    ├── params_stepstone.py          ← 可调参数 + 每轮调参结论（task_16dof.py 第 49-157 行）
    ├── env_cfg_stepstone.py         ← 训练配置（env_cfgs.py 的 stepstone_env_cfg 函数）
    └── register_stepstone.py        ← 任务注册代码（register() 里的那几行）
```

**集成方法**：把 `src/` 下的两个文件分别复制到项目的对应目录（覆盖同名文件），
`config/` 下三个文件是**摘录**，按文件头的说明粘回 `env_cfgs.py` / `task_16dof.py`
的对应位置——它们依赖文件内的其它基础设施，不能单独 import。
