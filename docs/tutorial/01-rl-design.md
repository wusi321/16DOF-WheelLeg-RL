# 01 · 任务设计：课程、约束与奖励

以本项目 `src/robot/config/env_cfgs.py`（梅花桩任务 `stepstone_env_cfg`）为例，
讲一个从零开始的任务该怎么搭。所有数值都是仓库里的真实值。

---

## 1. 先把"接口"定死：观测、动作、控制频率

| 项 | 本项目取值 | 为什么这么定 |
| --- | --- | --- |
| 物理步长 / 策略频率 | 0.005 s / 50 Hz（`decimation=4`） | 轮足需要较硬的接触，200 Hz 物理够稳 |
| 动作 | 16 维：12 个腿关节**位置** + 4 个轮子**速度** | 腿用位置控制好训，轮子必须用速度控制（否则学不会"滚"） |
| Actor 观测 | 53 维本体 + 273 维局部高度扫描 = **326** | 梅花桩必须"看地面"，只给本体状态学不出来 |
| Critic 观测 | 额外给线速度、轮地接触 | 非对称 actor-critic，critic 可以用特权信息 |
| 地形感应 | 21 × 13 网格、1.6 × 1.0 m、0.08 m 分辨率 | 分辨率要比桩宽（0.2 m）细，否则"看不见桩" |

> 经验：**地形类任务，高度扫描是必需品**。本项目不加扫描时，策略只能靠"撞了才知道"，
> 训练 500 迭代都学不会上桩。

## 2. 课程规划（Curriculum）

课程要解决的是"任务太难，随机策略永远拿不到第一个正样本"。

### 2.1 地形难度：10 档 + 按迭代**封顶**

```python
# env_cfgs.py
STEPSTONE_NUM_LEVELS = 10          # 第 i 行难度 d = i / 9
cfg.curriculum = {
    "terrain_levels": CurriculumTermCfg(
        func=stepstone_levels,
        params={"goal_distance": 6.8, "min_progress_frac": 0.75},
    ),
}
```

`stepstone_levels`（`src/robot/mdp/stepstone.py`）里同时做了三件事：

1. **升级**：本回合沿 +x 的净位移 > 6.8 m（进入终点平台）→ level += 1；
2. **降级（带迟滞）**：净位移 < 0.75 × 6.8 且**连续失败 2 次** → level -= 1；
3. **封顶**：`level_cap = common_step_counter // 1200`（每 1200 个策略步放行一级，
   ≈ 50 迭代一级），超过封顶的环境**随机撒回 [0, cap]**，不是一律压到 cap。

为什么要"封顶 + 随机撒"：

- 不封顶：策略在第 30 迭代就靠运气升到 9 级，然后全场失败，课程失效；
- 封顶但压到 cap：所有环境挤在同一级，会出现**整批同步翻转**
  （全升 → 全降 → 全升，`upgraded` 在 0 和 1 之间跳），本项目第 2 轮就栽在这；
- 概率升级（`promote_prob=0.5`）+ 随机撒：同一时刻既有"刚上来的"也有"还没升的"，
  分布被摊开，`mean` 才会平滑上升。

### 2.2 速度指令：跟着跟踪率走

```python
"command_x_levels": CurriculumTermCfg(
    func=command_levels_adaptive,
    params={"reward_term_name": "track_lin_vel_x", "target_ratio": 0.6,
            "initial_range": (0.3, 0.5), "delta_command": 0.05},
),
```

指令范围从 (0.3, 0.5) 起步，当 `track_lin_vel_x` 的 EMA 超过 0.6 就放宽一档（最多 0.8）。

> ⚠️ **踩过的坑**：一开始用 `forward_progress` 当"跟踪率"，而它是净位移速率、
> 没有上限——跑得越快值越大，课程立刻被打满，速度指令形同虚设。
> **课程的归一化项必须是"有界且真正衡量目标"的奖励项。**

## 3. 行为约束：用终止项和惩罚项划定"不能做什么"

约束分三类，优先级从高到低：

### 3.1 硬终止（episode 直接结束）

```python
cfg.terminations = {
    "time_out":          TerminationTermCfg(func=envs_mdp.time_out, time_out=True),
    "bad_orientation":   TerminationTermCfg(func=..., params={"limit_angle": 1.047}),  # 60°
    "base_ground_contact": TerminationTermCfg(func=..., params={"sensor_name": "body_collision"}),
    "base_too_low":      TerminationTermCfg(func=..., params={"threshold": 0.15}),
    "goal_reached":      TerminationTermCfg(func=reached_goal, params={"distance": 6.8}),
    "nan_detection":     TerminationTermCfg(func=envs_mdp.nan_detection),
}
```

- `time_out` 必须标 `time_out=True`，这样值函数在超时处**正常 bootstrap**；
  如果当成普通终止，长回合任务的价值估计会有系统偏差。
- **成功终止要和失败终止分开**：`goal_reached` 是"好事结束"，绝不能也罚。

### 3.2 软约束（每步惩罚）

| 奖励项 | 权重 | 约束什么 |
| --- | --- | --- |
| `flat_orientation` | −0.5 | 机身保持水平（梅花桩上翻车 90% 从倾斜开始） |
| `body_height` | −1.0 | 机身高度不能塌（防"蹲着蹭"） |
| `undesired_contacts` | −0.5 | 机身/大腿撞地 |
| `joint_pos_limits` | −5.0 | 关节撞限位 |
| `joint_torques` / `joint_power` | 小负值 | 省力、平滑 |
| `action_rate` | −0.01 | 动作变化率（抑制抖动） |
| `wheel_slip` | −0.05 | 轮子空转（梅花桩上空转 = 打滑掉坑） |
| `pit_contact` | −2.0 | ≥2 个轮子踩到坑底（赛规：半个以上足底着地即判失格） |

### 3.3 反"作弊"约束（本项目特有）

| 奖励项 | 权重 | 针对的行为 |
| --- | --- | --- |
| `airborne` | −1.0/步 | 桩区上空、四轮全部离地（**飞越**） |
| `overspeed` | −0.5 × 超出量 | 实际速度超过指令 +0.3 m/s（**狂冲**） |
| `time_out` | −10 × (1 − dx/6.8) | 磨时间（越近终点罚越轻，避免"不敢动"） |
| `stone_touch` | +2/根 | 逐桩接触（赛规要求） |
| `all_stones` | +20 | 踩满整段 |

> 这三条不是一开始就该有的，它们是**看 play 录像 + 曲线**之后补的。
> 见第 5 节。

## 4. 奖励配置：用"量纲"和"期望值"配权重

不要凭感觉写数字。做法：**先估每个回合的期望收益，再让总账为正**。

以本项目当前配置为例（回合 30 s、42 根桩、路程 6.8 m）：

| 项 | 单次/单步 | 一个成功回合的大致总量 |
| --- | --- | --- |
| `goal_reached`（× 覆盖率打折） | +120 × (0.2 + 0.8·cov) | +120（覆盖 1.0 时） |
| `stone_touch` | +2 / 根 | +84（42 根） |
| `all_stones` | +20 | +20 |
| `forward_progress` | +1.5 × clip(Δx/(dt·0.8), −1, 1) | ≈ +1.5 × 8.5 s (6.8/0.8) ≈ +13 |
| `track_lin_vel_x` | +0.8 × exp(−err²/σ²) | ≈ +24（30 s × 0.8） |
| 姿态/高度/滑移等 | 小负值 | −10 ~ −20 |
| 超时（未完成时） | −10 × (1 − dx/6.8) | −10（起点）/ −0.3（终点前） |
| 摔倒 | −10 | −10 |

几条经验：

1. **稀疏项要够大，但不能压过"任务本身"**。`goal_reached=120` 约等于一次
   完整"逐桩 + 踩满"收益（84+20=104）——刚好让"过终点"比"慢慢摸桩"更值。
2. **有界化**：`forward_progress` 一定要 `clip`。无上限的进度项会奖励"跑得越快"，
   本项目第 1 轮因此学会滞空飞越（实测 2.4 m/s，指令只有 0.3–0.8）。
3. **失败代价要 > 摆烂代价**。曾经把超时设成 −20、摔倒 −10，结果策略
   "过不去就赶紧摔"（`stone_coverage` 从 0.45 崩到 0.07）。现在：摔倒 −10、
   超时按距离缩放，最差 −10。
4. **用"按进度打折"代替"全有全无"**：`goal_reached × (0.2 + 0.8·coverage)`
   让"跳过一半桩冲过去"只拿 60%，比直接判零更容易学。

## 5. 三个真实的反面案例（这就是调 RL 的日常）

### 案例 A：滞空飞越（第 1 轮，`2026-10-26_22-26-00`）

| 现象 | 数值 |
| --- | --- |
| 回合长度 | 300 → **58 步**（1.16 s 走完 2.8 m） |
| 实际速度 | ≈ 2.4 m/s（指令 0.3–0.8） |
| `stone_coverage` | **0.43** |
| `track_lin_vel_x` 奖励 | 0.0023（几乎不跟指令） |

**原因**：终点奖励与覆盖率无关 + 进度项无上限 → 弹道飞越最省事。

**修复**（`c64bb45`）：终点奖励按覆盖率打折、加 `airborne` / `overspeed` 惩罚、
踩桩判定要求**真实接触**（接触传感器）。

### 案例 B：趴在桩上磨时间（第 2 轮，`2026-10-27_07-56-35`）

| 现象 | 数值 |
| --- | --- |
| `mean_reward` | 10 → **37**（还在涨） |
| 回合长度 | 200 → **900 步**（= 20 s 超时上限） |
| `upgraded` | 0.95 → **0.05** |
| `stone_coverage` | 涨到 **0.85**（桩都摸到了，就是不过线） |

**原因**：`stone_touch=+5`×16 + `all_stones=+20` ≈ 100，比"过终点 60×0.85≈53"更值，
且超时无惩罚 → 摸桩 + 耗时间是最优解。

**修复**（`6843e16`）：终点 60 → 120，新增超时惩罚，`stone_touch` 5 → 2。

### 案例 C：平推（第 4 轮，`2026-10-28_08-28-02`）

| 现象 | 数值 |
| --- | --- |
| `upgraded` | 稳定 0.5（不升不降） |
| `stone_coverage` | 卡在 **0.52** 不再上升 |
| 回合长度 | 稳定，不摔 |

**原因**：为了"能过"把中心距从 0.60 收到 0.45（净空 0.32 m < 轮距 0.385），
轮子任何时候都有支撑 → 一路平推，学不到踩桩。

**修复**（`f18cf50` → `efc378c`）：恢复实场间距，改**单桩交错**布局，
每跳距离由 `max_step = 0.46 m` 封顶——既跨得过、又必须真的踩。

> **共同规律**：三次崩都不是 PPO 崩，而是**奖励结构被绕过**。
> 判据见 [02-wandb.md](./02-wandb.md)：损失/熵/lr 都正常，只有任务指标崩。

## 6. 验收标准（每次训练前先写下来）

| 阶段 | 指标 | 通过线 |
| --- | --- | --- |
| 能站起来 | `Episode_Termination/time_out` 早期不飙、`base_z` 有数据 | 前 20 迭代 |
| 能过 | `goal_reached` 终止数 > 0 并上升 | 前 100 迭代 |
| 按规则过 | **`stone_coverage` ≥ 0.90** | 200 迭代 |
| 过得好 | `flat_orientation` 不随迭代恶化、`mean_leg_action_acc` 平稳 | 全程 |
| 课程 | `terrain_levels/mean` 单调上升，`upgraded` 0.3–0.6 | 全程 |

**只要有一项不达标，就不要继续加迭代**——加迭代只会放大已有问题。
本项目第 2 轮多的 100 个迭代、第 3 轮 700 之后的 100 个迭代，都是这么浪费掉的。
