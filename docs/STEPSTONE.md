# 梅花桩任务（Robot-StepStone-v0）

按 `16DOF_RL.md` 的讨论实现，对应 `Robocon2027.xml` 里的 `stepping_stones_01_*` 段。

## 1. 实场参数 vs 训练参数

实场（从 XML 里量出来）：

| 项 | 值 |
| --- | --- |
| 桩体 | `size = 0.1 0.1 0.1` → **0.20 × 0.20 × 0.20 m** |
| 桩顶高度 | 0.20 m（底层在地面 z=0） |
| 两条桩列 | `y = 2.2` / `y = 1.8` → 横向中心距 **0.40 m**（约等于轮距 0.385 m） |
| 同列前后中心距 | **0.60 m**（大于轴距 0.387 m，纯滚动过不去） |
| 两列错位 | **0.30 m** |
| 数量 | 每列 3 根，共 6 根 |

训练地形（`src/robot/terrains/stepping_stones.py`，单个 patch **8.0 × 1.6 m**，通行方向 2026-10-28 由 4.0 m 翻倍）。
逐级俯视图见 [`docs/images/terrain_levels.png`](images/terrain_levels.png)（`uv run python tools/plot_stepstone_terrain.py` 重新生成）：

| 项 | 难度 0 | 难度 1（= 实场） |
| --- | --- | --- |
| 桩高 | 0.06–0.08 m | 0.18–0.20 m |
| 前后中心距 | 0.28 m | 0.45 m（原 0.60，2026-10-28 收紧） |
| 两列错位 | 0 | 0.18 m（原 0.30，2026-10-28 收紧） |
| 位置扰动 | 0 | ±0.03 m |
| 缺桩概率 | 0 | 0（2026-10-28 起关闭，见下） |
| 桩列横向间距 | 0.40 m（固定） | 0.40 m |
| 起/终点平台 | 各 0.8 m | 各 0.8 m |

> **缺桩已关闭**：缺一根会让同侧相邻两跳变成 2×中心距（最高 1.1 m），机器人
> 没有支撑必然摔（play 里能看到卡在第一根桩后）。难度现在全部由桩高 / 中心距 /
> 错位 / 净空承担；等策略能稳定通过后再逐步放开 `_MISSING`。
>
> **错位改为正弦包络**：`stagger(k) = stagger × sin(π·k/(n-1))`，两端为 0、中间最大。
> 原来边排强制 0、里面满错位，会在「边排 → 第一排中间」形成 pitch + stagger（最高
> 0.9 m）的大跨，那正是之前卡住的位置。

桩区默认做成 **0.6 m 深的坑**（`pit_depth`），掉下去会触发 `base_ground_contact` /
`base_too_low` 终止，逼策略真的踩桩，而不是从地面绕过去；把 `pit_depth=0.0`
就退回实场“桩立在地面上”的形态。

## 2. 课程（难度 → 阶段）

地形生成器 `curriculum=True`、`num_rows=10`，第 i 行难度 `d = i / 9`：

| 难度 | 阶段 | 桩高 | 中心距 | 错位 | 噪声 | 缺桩 |
| --- | --- | --- | --- | --- | --- | --- |
| 0.00–0.15 | 1 低矮密集桩 | 0.06–0.10 | 0.30–0.32 | 0–0.05 | 0 | 0 |
| 0.15–0.30 | 2 目标尺寸固定桩 | ~0.10 | 0.32–0.35 | 0.05–0.10 | 0 | 0 |
| 0.30–0.50 | 3 随机交错桩 | 0.10–0.15 | 0.35–0.45 | 0.10–0.20 | 0–0.02 | 0 |
| 0.50–0.75 | 4 目标难度 | 0.10–0.18 | 0.45–0.55 | 0.20–0.26 | 0.02 | 0–5% |
| 0.75–1.00 | 5 鲁棒性阶段 | 0.18–0.20 | 0.55–0.60 | 0.26–0.30 | 0.03 | 5–10% |

升级/降级（`src/robot/mdp/stepstone.py: stepstone_levels`）：

- **升级**：本回合机身沿 **+x 的有符号位移** `> 6.8 m`（即进入终点平台），与成功判定
  `reached_goal` 同一口径；
- **降级**：沿 +x 的位移 `< 0.7 m`（全程 25%），说明当前难度处理不了；
- 逐环境结算，在 `_reset_idx` 里、reset 之前调用（读到的是回合结束时的位置）；
- 首次 reset（`episode_length_buf == 0`）跳过，避免“机器人还停在世界原点”被误判升级。

> 早先版本用 XY 欧氏距离，横向漂移会被算成“前进”，走歪的回合也可能升级；现在与
> 成功条件一致，只看 +x 位移。

外加 `command_x_levels`（`src/robot/mdp/curriculums.py: command_levels_adaptive`）：
`forward_progress` 的**每步平均跟踪率**超过 0.6 就把速度指令范围向上抬 0.05 m/s，
初始 0.3–0.5 m/s，上限由 `ranges.lin_vel_x`（0.3–0.8）约束。

> 归一化用**实际回合时长**（`episode_length_buf × step_dt`）。早先固定除以
> `episode_length_s`（现在是 30 s），而成功/摔倒的回合远短于它，会把跟踪率系统性压低
> （6 s 的回合只算出 0.24，真实是 0.80），速度课程因此永远升不上去。

## 3. 奖励

| 奖励项 | 权重 | 作用 | 对应讨论 |
| --- | --- | --- | --- |
| `forward_progress` | +1.5 | 机身实际速度投影到指令方向，归一化到 0.8 m/s | 目标方向进度（不用轮速） |
| `track_lin_vel_x` | +0.8 | 速度跟踪（x） | 速度命令跟踪 |
| `track_ang_vel_z` | +0.4 | 偏航角速度跟踪 | 转向 |
| `flat_orientation` | -0.5 | 俯仰/横滚 L2 | 姿态稳定 |
| `body_height` | -1.0 | 机身高度低于 0.18 m 或高于 0.75 m 的部分 | 机身高度合理性 |
| `wheel_slip` | -0.05 | 接触轮 `|ω·r − v_x|` | 轮滑代价 |
| `joint_torques` | -2.5e-5 | 力矩 L2 | 能耗 |
| `joint_power` | -2.0e-5 | `Σ|τ·q̇|` | 机械功率 |
| `action_rate` | -0.01 | 动作变化率 | 控制平滑 |
| `joint_pos_limits` | -5.0 | 软限位越界 | 关节保护 |
| `undesired_contacts` | -0.5 | 机身/腿撞地形（轮与桩顶接触不算） | 禁止的机身碰撞 |
| `goal_reached` | +60.0 | 到达终点平台一次 | 任务成功 |
| `is_terminated` | -50.0 | 非超时终止（摔倒/撞地/出界） | 跌倒或严重失败 |
| `stone_touch` | **+3.0** | 每踩上一根**新**桩（整回合只算一次） | 规则：「每个桩顶面至少与足底接触一次」 |
| `all_stones` | **+10.0** | 整段每根桩都踩到一次（一次） | 规则：踩满才算完整通过 |
| `pit_contact` | **-2.0/步** | ≥2 个轮子踩到坑底（= “1/2 以上足触地”） | 规则：触地即需重新越障 |

> 成功时 `goal_reached +60` 与 `is_terminated -50` 同时结算，净 +10；如果之后
> 觉得“成功太便宜/太贵”，只需调这两个权重，不必动其它项。
>
> “踩桩”判定见 `src/robot/mdp/stone_coverage.py`：轮子最低点（轮心 − 0.086 m）与桩顶
> 高度差 ≤ 4 cm、且轮心落在桩顶面内（±3 cm）时记为接触；桩体从编译后的场景里按几何
> 特征（terrain body 内、水平半尺寸 = `stone_size/2`、顶面高于平台）自动提取，**不依赖
> geom 名字**（地形生成器会重命名所有 geom）。

## 4. 终止条件

| 终止 | 说明 |
| --- | --- |
| `time_out` | 30 s 超时（truncation，值函数正常 bootstrap；路程翻倍后由 20 s 调整） |
| `bad_orientation` | 倾角 > 60° |
| `base_ground_contact` | 机身（`base_link`）接触地形 |
| `base_too_low` | 机身相对地形原点低于 0.12 m（掉进桩间/坑里） |
| `goal_reached` | 机身沿 +x 进入终点平台（成功，按终止处理） |
| `nan_detection` | 物理状态出现 NaN |

## 5. 观测与动作

- 动作：16 维不变（12 腿位置 + 4 轮速）。
- Actor 观测：**326 维** = 53 维本体状态（角速度/重力/指令/腿位置/腿速度/轮速/
  上一动作）+ **273 维局部高度扫描**（`height_scanner`：21 × 13，1.6 × 1.0 m，
  分辨率 0.08 m，`ray_alignment="yaw"`）。
- Critic 观测：333 维（在 53 维基础上加线速度 3 + 轮地接触 4 + 同一张高度图 273）。

> 讨论里建议 0.05 m 分辨率 / 120° 视场 / 2.0 m 感知距离，并显式输出“有效性掩码”。
> 这一版先用 mjlab 现有的矩形射线网格（0.08 m），掩码靠“射线打不到 = 返回
> `max_distance`”隐式表达。要上真实 LiDAR 噪声/遮挡，改 `_make_base_env_cfg()` 里
> 的 `terrain_scan`（`RayCastSensorCfg`）和这里的观测项即可。

## 6. 训练

```bash
uv run train Robot-StepStone-v0          # 从零训练
uv run play  Robot-StepStone-v0          # 回放（需 GPU）
uv run python tools/smoke_build_env.py   # 4 个任务的 build/step 自检
```

建议流程：

1. 先 `Robot-Flat-v0` 把 16 维控制、站姿、速度跟踪跑通（讨论的阶段 0）；
2. 再 `Robot-StepStone-v0`：它会从阶段 1 的低矮密集桩自动升级；
3. 训练早期把 `num_envs` 减到 1024 以内可显著加快 debug 迭代；
4. 观察 TensorBoard 里的 `Curriculum/terrain_levels/*`、`Episode_Reward/goal_reached`、
   `Metrics/stepstone/goal_reached` 判断课程是否在推进。

## 7. 与讨论稿的差异 / 待办

- **没有真实 LiDAR 模型**：用 mjlab 的射线网格代替点云，无噪声、无丢点、无遮挡
  建模（对应讨论第 4.4 节的随机化顺序，后续再加）。
- **悬空/落轮的可达性检查**：目前只做了“同排两条桩列不能同时缺失”和边界裁剪，
  没有做几何连通性/可达性求解（讨论 2.4 节）。
- **地形种子记录**：依赖 mjlab 的 `TerrainGeneratorCfg.seed`（全局），还没有
  逐 episode 的种子日志。
- **成功条件**是“机身进入终点平台”，同时新增了逐桩踩踏约束（见 §3 的 `stone_touch` /
  `all_stones` / `pit_contact`）：跳桩通过的策略拿不到铺满奖励，`all_stones` 只在整个
  patch 的每根桩都接触过之后结算一次。逐桩判定用几何近似（轮底与桩顶高度差 + 落点），
  没有用接触力传感器，因此轮子从桩边擦过但未承重时**可能**被记成接触（容差 4 cm）；
  真机上再结合 `feet_ground_contact` 力阈值收紧。
