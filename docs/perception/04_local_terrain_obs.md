# 04 · 局部地形观测定义（Local Terrain Observation）

本文件定义**策略唯一能看到的地形表示**。它必须同时满足：

- 官方梅花桩（`2027年足式机器人挑战赛-V1.0.pdf`：**200×200×200 mm** 方块、同排中心距 **600 mm**、两排中心距 **400 mm**、两端 **800×800×200 mm** 平台、表面绿色水性漆）需要看清**桩顶、桩边、桩间坑**；
- 轮足“优先滚动通过”需要知道**轮子落点**处的地面高度；
- 真机 Odin1 与仿真射线扫描都能生成同一套数。

## 1. 坐标系

| 项 | 定义 |
| --- | --- |
| 参考系 | `base_link`（机身），**yaw 对齐**：只跟随航向，不跟随俯仰/横滚（与 `ray_alignment="yaw"` 一致） |
| 轴向 | x 前、y 左、z 上（REP-103） |
| 原点 | 机身质心处的 `base_link` 原点（MuJoCo 中即 `root_link_pos_w`） |
| 高度语义 | `h = z_base − z_ground`，**正值表示地面在机身下方 h 米** |
| 推论 | `h` 越小 = 地面越高（障碍）；`h` 越大 = 越深（坑）；平地时 `h ≈ 0.32–0.36`（等于机身高度） |

> 这个符号约定容易搞反：**桩顶的 `h` 比平地小**。桩高 0.2 m 时，`h_stone ≈ h_flat − 0.2`。

## 2. 栅格几何（已在本仓库逐项验证）

| 分辨率 | **0.08 m** | `src/robot/config/env_cfgs.py:206` |
| x 范围 | **[−0.80, +0.80] m**（21 点，对称） | 探针实测 |
| y 范围 | **[−0.50, +0.46] m**（13 点，**左偏 2 cm，不对称**） | 探针实测（`size_y=1.0` 取整导致） |

### 2.1 安装位姿（2026-10-26 确认）

Odin1 装在**机身最前端、头顶**（正前方最高点）。由此带来的三条约束：

| 约束 | 影响 | 处理 |
| --- | --- | --- |
| 视点高、前伸 | 前向覆盖远、脚下与后方是盲区 | 栅格前方（x>0）肯定有效，`x<0` 区域大概率 `valid=False` → 用静态掩膜（`augment.make_rect_mask`）在训练里对齐 |
| 俯视角度取决于安装俯仰 | 近端盲区半径 ≈ `h / tan(θ + 45°)` | 俯仰角待标定（V4 剩余项），标定后写进 `perception.yaml` 的 `mount.rpy_deg` |
| 机身/腿部自遮挡 | 后方与两侧边缘出现洞 | 保留 `valid=False`，不插值 |

公式：`r_near = h / tan(θ + 45°)`，`h` 为传感器离地高度、`θ` 为光轴下俯角、垂直半 FOV 45°（90° V）。
例：`h = 0.5 m`、`θ = 20°` → 近端盲区 `0.5 / tan(65°) ≈ 0.23 m`；上边缘射线（`θ − 45° = −25°`）指向水平以上，
**远端没有几何边界**，实际由量程（30 m）与掠射角下的点密度决定。
**标定前不做假设**：`θ` 一变，近端盲区和掩膜都要重算。

为什么是 0.08 m：

- 桩 0.2 m → 2.5 个格子，桩顶至少有 2 格完整落点，足够判断“能不能站”；
- 再粗（0.1 m）桩顶只剩 2×2，边缘信息不足；再细（0.05 m）点数 ×2.56，训练和真机处理成本都上涨；
- 与真机稀疏性匹配：3 m 内每格 5–85 点（见 03 文档 §3），0.08 m 是“有点可用”和“不够细”的平衡点。

为什么是 1.6×1.0 m：

- 轮距 0.385 m、机身前伸约 0.28 m，1.0 m 横向覆盖 ±0.5 m，足够覆盖两个轮子与侧向离桩；
- 前向 0.8 m 在 1.0 m/s 下是 0.8 s 的预判量，在 1.5 m/s 下 0.53 s，够做一次抬腿决策；
- 与 Odin1 在 0.4 m 安装高度、俯视 30° 时的地面覆盖（约 0.7–3 m）在近端重叠。

## 3. 数值定义

```text
height_m[r][c] ∈ ℝ        # 米；见 §1 语义
valid[r][c]    ∈ {0,1}    # 该格是否有可信测量
```

- `valid=0` 时 `height_m` 的数值**无意义**（允许放大哨兵，但编码器会忽略）。
- 编码进策略前（v1，冻结）：

```text
obs[i] = clip( valid ? height_m : 5.0 , −1.0, +1.0 )
```

  即：**无效 → 1.0**；`h > 1.0`（深坑/悬空）→ 1.0；`h < −1.0`（地面高过机身 1 m，实际不会出现）→ −1.0。

- 由此带来的已知歧义（v1 接受，v2 解决）：`h ≥ 1.0` 的深坑与“没有回波”在观测里都是 1.0。
  仿真里坑深 0.6 m、机身 0.32 m → `h ≈ 0.92`，仍在 1.0 以内，所以桩间坑是**可区分**的；
  只有真正超过 1.0 m 的落差才会和丢点混淆。

## 4. 有效性（invalid）处理

| 情形 | `valid` | 原因 |
| --- | --- | --- |
| 射线未命中（>5 m） | 0 | 仿真：`distances < 0` |
| 无回波/超量程/低置信度 | 0 | 真机：过滤后该格无点 |
| 点在 `base_link` 后方或被机身穿透 | 0 | 真机自遮挡 |
| 安装位姿导致该格在 FOV 外 | 0 | 真机固定掩膜（V4 标定后写死） |

**不做插值**。桩边缘插值会制造假斜坡，比“看不见”更危险。允许的唯一补洞：3×3 邻域内
有有效点的孤立空格做一次中值填补（可选，默认关）。

## 5. 时间戳

| 项 | 约定 |
| --- | --- |
| `stamp_ns` | 该帧点云的**采集时刻**（点云 `header.stamp`；仿真为当前步仿真时间） |
| 帧龄 | `now_monotonic − recv_monotonic`（不依赖设备时钟） |
| 最大可用帧龄 | 300 ms（超过 → 整帧 `valid=0`，观测恒 1.0） |
| 保持策略 | 零阶保持，最多 200 ms；不插值 |
| 每点时间 | 真机 `offset_time` 只用于去畸变（内部），**不进观测** |

策略侧不做任何时间特征（不喂 `dt`、不喂帧龄），避免把“延迟”编码成可被利用的捷径。

## 6. 必须保留的四类信息

### 6.1 桩顶（stone top）

- 判据：`valid` 且 `h < h_flat − 0.05`（比当前平地低 5 cm，即高起 ≥5 cm），且该格 3×3 邻域内
  多数格子同高（避免单点飞点）。
- 用途：判断“轮子能不能压上去”“抬腿踩哪里”。
- 仿真侧已知真值：`BoxSteppingStonesTerrainCfg` 的桩顶高度 = `base_z − stone_height`。

### 6.2 桩边（edge）

- 定义：相邻格子高度跳变 `|Δh| > 0.04 m`（半个格子、5 cm 以内）且两侧都 `valid`。
- 用途：识别“前方有台阶/桩沿”，决定是滚上去还是抬腿。
- 真机注意：边缘处点云稀疏，`valid` 可能缺失 → 边缘检测要容忍单侧缺失（用 3×3 邻域最大跳变）。

### 6.3 可通行区域（traversable）

按 `h` 分档（以机身高度 0.32 m、轮半径 0.086 m 为基准）：

| `h` 区间 | 含义 | 动作倾向 |
| --- | --- | --- |
| `h > 0.28` | 地面在轮底附近或更低（平地/下坡） | 直接滚动 |
| `0.20 < h ≤ 0.28` | 地面已接近轮底（抬升 ≤ 8 cm） | 滚动可通过，可能轻微抬腿 |
| `0.14 < h ≤ 0.20` | 台阶/桩顶 8–18 cm | 抬腿 |
| `h ≤ 0.14` | 高于 18 cm，超过单步抬腿舒适区 | 绕行/放弃 |
| `valid=0` | 未知 | 保守（按障碍处理，见 §8） |

阈值来源：轮半径 0.086 m、站姿腿长 0.359 m、桩高 0.1–0.2 m（`16DOF_RL.md` 规划）；
`0.14/0.20/0.28` 是把 0.359 减去 0.08/0.16/0.08 得到的工程分档，**不是物理硬限**，可随策略训练调整。

### 6.4 轮子落点（wheel landing）

用**本体运动学**（不是感知）算出四个轮心在 `base_link` 中的位置：

```text
p_wheel[i] = (x_i, y_i, −0.273)        # 站姿下轮底相对机身 z ≈ −0.273（0.359 − 0.086）
cell[i]    = 栅格化(p_wheel[i])
h_land[i]  = height_m[cell[i]]  (if valid)
```

判据：轮底世界高度 `z_base − 0.273`，地面 `z_base − h`；当 `h > 0.273` 时**地面高于轮底**，
说明轮子必须先“上台阶”。四个轮子的 `h_land` 与当前平地 `h_flat` 的差，就是“这次滚动会不会撞沿”的直接度量。

真机上这一步用里程计位姿 + 关节角算 `p_wheel`，与感知同帧；仿真里用 MuJoCo 前向运动学，结果一致。

## 7. 与全局定位的边界

- 本观测**只有 `base_link` 系**，不含 `map`/`odom` 绝对坐标，不含朝向（yaw 已对齐）。
- 全局信息（目标点、路径）只作为**相对量**进入指令层，不进入 `TerrainFrame`。
- 因此策略对“机器人在世界哪里”天然不变，重定位跳变不会污染输入。

## 8. 未知区域的处理原则

`valid=0` 在观测里是 1.0（“地面很远”），语义上等价于“这里没有障碍”或“这里深不见底”。
两种解释都危险，所以：

1. **训练侧**：仿真中随机屏蔽部分格子（尤其桩后、机身两侧），让策略见过“看不见”的情形；
2. **控制侧**（第三阶段）：`valid` 掩膜同时给到上层决策——若机器人**正前方 0.3 m 内**出现连续
   无效格，限速到 0.3 m/s 以下，直到恢复；
3. **不把“未知”当成“可通行”** 写进奖励：`forward_progress` 只在 `valid` 覆盖足够时给全额奖励
   （现有 StepStone 奖励已按 x 前进给分，第 3 阶段再加这条门控）。
