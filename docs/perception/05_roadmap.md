# 05 · 分阶段实施计划与验收标准

原则：**先仿真、再离线回放、最后上真机**；每一阶段都有可量化门槛，过不了就停在这一阶段修。

本文件只是计划：**当前没有任何代码落地**（`src/robot/` 未改动，未新增依赖）。

## 阶段总览

| 阶段 | 目标 | 依赖 | 产出 | 是否改 RL 环境 |
| --- | --- | --- | --- | --- |
| P0（本轮） | 接口调查 + 设计 | 无 | `docs/perception/` 五份文档 | 否 |
| P1 ✅ | 仿真侧接口 + 编码器 + 回归测试 | numpy/torch（已有） | `perception/` 纯数组模块 + 42 个单测（已完成 2026-10-26） | **否**（独立模块，未接入训练） |
| P2 | 真实数据离线验证预处理 | 一台录好的 bag / npz | 回放工具 + 对齐报告 | 否（只读） |
| P3 | 真机闭环 | 整机 + Odin1 + 机载算力 | 机载节点 + 策略部署 | 新增 `Robot-*-Perception-v2` 任务 |

## P1 · 仿真侧接口与观测（✅ 已完成 2026-10-26）

### 任务

1. 新增独立包 `perception/`（**不 import `mjlab` 之外的重依赖，不 import `rclpy`**）：
   - `perception/frame.py`：`TerrainFrame` 数据类 + `SCHEMA_VERSION` + 校验函数（形状/量纲/单调时间戳）。
   - `perception/encode.py`：`encode(frame) -> float32[273]`，规则见 02 文档 §5。
   - `perception/sources/sim.py`：从 `env.scene["height_scanner"]` 读一帧。
   - `perception/sources/replay.py`：读 `.npz`。
   - `perception/augment.py`：噪声/丢点/FOV 掩膜/延迟（训练用，默认关闭）。
2. 新增测试 `tests/test_perception_*.py`（pytest，CPU，秒级）：
   - 栅格几何断言（21×13、x/y 范围、索引顺序）；
   - 编码器与 `safe_height_scan` 逐元素一致（20 个随机重置状态）；
   - 无效值语义（全 miss → 全 1.0；0.2 m 桩 → 桩顶 `h≈0.12`）；
   - `TerrainFrame` 校验能拒绝错形状/NaN/时间戳倒退。
3. **不接入训练**：`Robot-StepStone-v0` 保持现状，避免破坏已有 300 迭代的基线。

### 验收

- [x] `uv run python -m unittest discover -s tests -t .` 全绿（42 项，CPU 0.3 s）。
- [x] 编码器与现有观测逐元素一致：`tools/check_perception_alignment.py` 在 Flat/StepStone 各 12 步 × 2 环境上 `max|diff| = 0.0`。
- [x] CI 的「静态检查」job 通过（新增 `compileall perception tests` + unittest 步骤）。
- [x] `python -c "import perception"` 在未安装 `rclpy` 的环境下成功（包内无 ROS 2 依赖）。

### 不做

- 不改 `height_scanner` 配置、不改奖励、不改任务注册、不加依赖。

## P2 · 真实数据离线验证（3–5 人日，含现场录制）

### 前置（必须先回答 03 文档 §8 的 Q1–Q5）

- 整机装配后标定 Odin1 安装位姿（V4）；
- ~~确认 `cloud_raw` 是否已去畸变~~：**已确认设备端已完成**（V3，2026-10-26）；
- 确认 `use_host_ros_time` 取值（建议 2）。

### 任务

1. 录制：里程计模式（`custom_map_mode: 0`）行走梅花桩赛道，`dtof_fps: 100`，QoS depth 4000；
   `ros2 bag record` 至少包含 `/odin1/cloud_raw`、`/odin1/imu`、`/odin1/odometry_highfreq`、`/tf`。
2. 转换：机载脚本把 bag → `.npz`（`TerrainFrame` 序列 + `debug` 计数）。**转换在机器人上做，
   训练机只读 npz**，训练环境不装 ROS。
3. 对齐：按 03 文档 §7 的方法，用真实轨迹在仿真里重放，得到参考高度图。
4. 调参：`confidence_min`、`cell_percentile`、`max_range`、补洞开关。
5. 产出报告：误差分布图（中位/90 分位）、覆盖率、时延、失败帧清单。

### 验收

| 指标 | 门槛 |
| --- | --- |
| 高度中位误差（双边 valid） | ≤ 3 cm |
| 高度 90 分位误差 | ≤ 8 cm |
| 覆盖率（3 m 内，273 格） | ≥ 85% |
| 桩顶高度误差 | ≤ 2 cm |
| 单帧处理时延（采集→`TerrainFrame`） | ≤ 100 ms（p95） |
| 确定性 | 同 bag 两次回放逐位一致 |
| 丢帧率（10 Hz 下） | ≤ 2% |

**过不了门槛的处理**：如果覆盖率或桩顶误差不达标，先改安装（抬高/前移），再考虑加第二颗传感器
或改用 `cloud_render`；不改 RL 结构。

## P3 · 真机接入（1–2 周，视机载算力）

### 任务

1. `PerceptionNode`（ROS 2 C++ 或 Python）：订阅点云 + TF + 高频里程计，输出 `TerrainFrame` 到
   共享内存环（与策略同机）或 UDP（跨机）。
2. 策略进程：读 `TerrainFrame` → `encode()` → 与仿真**同一套**归一化与动作缩放 → 轮足。
3. 安全层：
   - `stale`/`no_data` → 速度指令归零（不是“继续用旧帧”）；
   - 前方连续无效格 → 限速；
   - 侧向倾角超限 → 直接停。
4. 新任务 id `Robot-StepStone-Perception-v2`：观测 = 273 高度 + 273 掩膜 + 4 轮落点高度（见 04 文档 §9），
   训练时带 P1 的增强；旧 `v0` 保留可回滚。

### 验收

| 指标 | 门槛 |
| --- | --- |
| 单帧端到端时延（采集→策略输入） | **≤ 500 ms（硬指标）**；目标 p95 ≤ 150 ms |
| 策略推理频率 | ≥ 45 Hz（50 Hz 目标） |
| 静止/平地行走 | 与纯本体策略无回退（同样速度下不摔） |
| 梅花桩通过率 | 10 次 ≥ 8 次（0.2×0.2 m、0.15 m 高、间距 0.6 m 同款布置） |
| 遮挡鲁棒性 | 人为挡住传感器 1 s，机器人只减速不摔 |
| 回滚 | 关闭感知后仍能按纯本体策略完成平地/缓坡 |

## 风险登记

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 安装位姿看不到脚前 0.5 m 地面 | 中 | 高 | 抬高/前伸安装；不行则加一颗向下短距传感器 |
| 4 m 外过稀、桩顶只剩 1–2 点 | 高 | 中 | 只依赖 3 m 内；远处按“未知”处理 |
| 桩体深色/哑光导致大量丢点 | 中 | 高 | P2 先测；必要时贴反光带（会改变任务，先确认规则） |
| 10 Hz 点云 + 处理延迟让策略“慢半拍” | 高 | 中 | 训练加延迟增强；降低行走速度上限 |
| 机载算力不足（ROS 2 + 点云处理） | 中 | 中 | 降低点云下采样；处理移到 C++；只在 3 m 内处理 |
| 训练用增强过强导致精度下降 | 中 | 中 | P2 报告里加“干净数据回测”，约束增强幅度 |
| 与导航层耦合导致策略依赖 `map` | 低 | 高 | 04 文档 §7 的硬约束 + 代码评审 |

## 里程碑判定（go / no-go）

- **P1 → P2**：编码器一致性测试通过 + 现场可稳定录制 bag。
- **P2 → P3**：全部 P2 门槛达标；若有 1 项不达标，只允许“改安装/改参数”一次，仍不达标则暂停真机接入。
- **P3 上线**：10 次通过 ≥ 8 次，且回滚开关验证有效。
